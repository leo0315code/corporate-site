# 企业官网 CMS 内容管理后台 · 使用说明

> 面向**运营 / 内容维护人员**与**部署方**。后台用于在线维护官网的
> 产品、新闻、案例、优势、关于我们、网站配置等 6 类内容，并查看访客留言与**操作日志**。
> 前台各页面通过公共 API 动态读取这些内容，**后台改完刷新前台页面即生效**。

- 技术栈：ThinkPHP 8（后端）+ Vite 5 / React 18（前端）+ MySQL 8
- 后台路径**可配置**（默认示例 `manage-x7k2`），前后端各读同一配置值
- 全站统一响应 `{ code, message, data }`，`code=0` 表示成功

---

## 一、后台入口与后台路径配置（部署方重点）

后台路由前缀由**环境变量**控制，前端与后端**同名同值**，两处必须完全一致：

| 端 | 文件 | 变量 | 示例 |
| --- | --- | --- | --- |
| 前端 | `frontend/.env.development`、`frontend/.env.production` | `VITE_CMS_PATH` | `/manage-x7k2` |
| 后端 | `backend/.env`（复制自 `.example.env`） | `CMS_PATH` | `/manage-x7k2` |

- 归一化规则：去尾斜杠、保证以 `/` 开头；示例值 `manage-x7k2` → `/manage-x7k2`。
- **未配置即不存在**：`CMS_PATH` 为空时，前端**不注册**后台路由、后端**不注册**后台 API，
  该前缀下整体返回 404 —— 不在任何默认路径暴露后台入口（安全默认）。
- 因此后台地址 = `https://<你的域名><VITE_CMS_PATH>`，例如 `https://www.example.com/manage-x7k2`。

> 开发期 Vite 已配置：`/api`、`{VITE_CMS_PATH}/api` 与 **`/uploads`** 均代理到后端
> `http://localhost:8000`；`{CMS_PATH}/login` 等**页面路由**仍由前端 SPA 处理，不受代理影响。
> （`/uploads` 代理用于后台预览上传后的图片。）

## 二、初始化（首次部署，一次性）

### 2.1 建表 + 迁移内容 + 创建管理员

```bash
cd backend
# 从示例复制环境变量并按需修改数据库连接（默认 root/root，库 corporate_site）
# Windows:      copy .example.env .env
# macOS/Linux:  cp .example.env .env

E:/ServBay/bin/php.cmd think cms:init      # 或已加入 PATH 时：php think cms:init
```

`cms:init` 命令职责（**幂等**，可重复执行）：

1. 执行 `database/cms.sql` 建表（`CREATE TABLE IF NOT EXISTS`；`message` 表按列存在性判断幂等 `ALTER`）。
2. 读取 `database/seed/cms-seed.json`，按业务主键 `updateOrCreate` 迁移 6 类内容。
3. 若 `admin_user` 无记录：生成**随机强初始密码**（≥12 位，含大小写 + 数字 + 符号）
   并以 bcrypt 落库，`must_change_password=1`；**账号名与初始密码打印到终端**。
   若已存在管理员则**跳过**（不覆盖已改密码）。
4. 终端输出导入统计：`products:8 / news:7 / cases:6 / advantages:4 / about:1 / site:1`。

### 2.2 迁移条数核对

| 内容 | 表 | 期望条数 | 源文件 |
| --- | --- | --- | --- |
| 产品 | `product` | 8 | `frontend/src/data/products.ts` |
| 新闻 | `news` | 7 | `frontend/src/data/news.ts` |
| 案例 | `case_item` | 6 | `frontend/src/data/cases.ts` |
| 优势 | `advantage` | 4 | `frontend/src/data/advantages.ts` |
| 关于我们 | `about` | 1 | `frontend/src/data/about.ts` |
| 网站配置 | `site_config` | 1 | `frontend/src/config/site.config.ts` |
| 管理员 | `admin_user` | 1 | `cms:init` 生成 |
| 操作日志 | `op_log` | 0（建表，随操作累积） | 运行时自动写入 |

> `frontend/src/data/*.ts` **保留**：既是迁移数据源，也是前台接口失败时的**降级兜底**。
> `frontend/src/config/site.config.ts` 同样保留，作为站点配置的**静态兜底值**（见 4.6）。

### 2.3 操作日志保留与清理（运维，周期性）

操作日志只追加、不修改；为控制体量，按**保留天数**定期清理**过期**记录：

```bash
cd backend
E:/ServBay/bin/php.cmd think oplog:clean              # 默认按 OPLOG_RETAIN_DAYS 清理
E:/ServBay/bin/php.cmd think oplog:clean --days=180   # 指定保留天数（覆盖配置）
E:/ServBay/bin/php.cmd think oplog:clean --days=3650  # 演练：保留 10 年 → 实际删除 0 条
```

- 保留天数来自 `backend/.env` 的 **`OPLOG_RETAIN_DAYS`**（示例 `180`）。
- 命令**分批删除**（避免长事务锁表）并打印删除条数；**幂等**，可重复执行。
- `--days` 必须 **≥ 1**，否则命令**报错退出（exit 1）**，防止误删全表。
- 清理命令**自身不写日志**（否则会产生「清理日志的日志」自循环）。
- 建议以**每日定时任务**（cron / 计划任务）方式运行。

## 三、登录与密码

### 3.1 登录

1. 打开后台地址（如 `https://www.example.com/manage-x7k2`），未登录会跳转登录页。
2. 输入**账号**与**密码**（`cms:init` 首次执行时终端打印的账号与初始密码）。
3. 登录成功：
   - 若 `must_change_password=1`（初始密码）→ **强制跳转「重置密码」页**，改密后方可进入；
   - 否则直接进入后台首页（概览）。

### 3.2 登录安全

- **失败锁定（账号 + IP 双维度）**：连续失败 5 次锁定 10 分钟；锁定期内即使密码正确也被拒绝。
- **限流**：同一 IP 每分钟超过 10 次登录请求 → `1008`「请求过于频繁」。
- **防枚举**：账号不存在与密码错误返回**同一**文案「账号或密码错误」（`1004`）。
- 会话 **Token 固定 2 小时**有效；登出 / 改密后旧 Token 立即失效。
- Token 存于浏览器 `localStorage['cms_token']`，走请求头 `Authorization: Bearer`，不写入 URL / 日志。

### 3.3 修改密码

- **强制改密**（首次登录）：输入**新密码 + 确认**；强度规则：长度 ≥ 8，含字母 + 数字，
  且不得与账号名相同。此为**独立整屏页**（登录前的闸门页，无后台外壳）。
- **常规改密**（登录后「修改密码」）：需输入**原密码 + 新密码 + 确认**；原密码错误 → `1007`。
  此页**位于后台外壳之内**（与产品/新闻等管理页一致，侧栏与顶栏均有入口），
  改完可随时经左侧导航切到其它模块。
- 改密成功后**清除登录态**，需用新密码重新登录。

## 四、内容维护（7 大模块 + 账号管理 + 操作日志）

登录后左侧导航进入各模块。列表页统一交互：右上「新增」、行内「编辑 / 删除」（删除二次确认）、
保存成功弹 Toast；搜索 + 分页（每页 10 / 20 / 50 可选）。

> **通用「刷新即生效」**：任意模块**保存 / 删除成功后，前台对应页面刷新即可看到最新内容**
> （前端会在保存成功后清除内容缓存）。

### 4.1 产品管理（`/products`）

- 字段：`id`（业务唯一标识 / slug，主键）、分类、名称、简介、详情、核心特点（多行，一行一条）、
  产品图片（**上传**）、图标标识。
- **id 默认由系统自动生成**（形如 `product-20261017-1a3f9`），通常**无需关心**：
  - 新增时展示为只读值，可点「换一个」重新生成；确需自定义时点「**手动指定**」改为输入；
  - **编辑时恒为只读** —— id 构成前台详情页 URL（`/products/:id`），改动会导致既有链接失效；
  - 若与已有 id 重复，保存时返回 `1001` 提示更换。
- **图片不再手填路径**：点「选择图片」从本机上传，自动落盘并回填路径（详见第六节）。
- 排序：默认按创建时间倒序。

### 4.2 新闻管理（`/news`）

- 字段：`id`（slug，默认自动生成）、标题、日期（`YYYY-MM-DD`，排序键）、分类、封面图（**上传**）、
  摘要、正文（保留换行分段，前台以 `whitespace-pre-line` 呈现）。
- 排序：按 `date` 倒序。新闻详情页「上一篇 / 下一篇」由后端按日期顺序返回。

### 4.3 案例管理（`/cases`）

- 字段：`id`（slug，默认自动生成）、客户名称、Logo（**上传**）、描述。
- 展示于首页「客户案例」区块。

### 4.3.1 图片上传（产品图 / 封面 / Logo 通用）

所有图片字段均为**上传控件**，无需手写路径：

| 项 | 说明 |
| --- | --- |
| 支持格式 | jpg / jpeg / png / webp / gif（**不接受 SVG**：同源 SVG 可执行脚本，存在存储型 XSS 风险；图标请转 PNG/WebP） |
| 大小上限 | 单张 ≤ **5MB** |
| 存储位置 | `backend/public/uploads/{product\|news\|case}/` |
| 文件命名 | 服务端随机 32 位十六进制（**丢弃原始文件名**，防路径穿越 / 覆盖） |
| 返回路径 | `/uploads/<分组>/<随机名>.<扩展名>`，自动写入对应字段 |
| 校验方式 | 服务端用 `finfo` 探测**真实 MIME**，并与扩展名**交叉校验**（防后缀欺骗）；白名单外一律拒绝 |

> 上传接口位于后台路径之下（`{CMS_PATH}/api/upload/image`）且**必须登录**，
> 未登录返回 `1003`；因此**不会**存在匿名上传入口。
> 前端会在选择文件时先做一次大小 / 扩展名预检，用于快速反馈；**最终以后端判定为准**，
> 后端返回的 message 会原样提示在字段下方。

### 4.4 优势管理（`/advantages`）

- 字段：`value`（突出数字 / 短语）、`label`（标签）、`desc`（说明）、`sort_order`（排序值，越小越靠前）。
- 展示于首页「数据与优势」区块与 Hero 首屏数字卡。
- ⚠️ **本模块主键为自增数字（非 slug）**：新增时**不要填写 id**（系统自动分配）；
  编辑时携带记录 id 即可。`sort_order` 可留空（按创建顺序）。

### 4.5 关于我们（`/about`，单例）

整页分区编辑后**一次性保存**，包含：

- 公司简介（长文本）、愿景、使命；
- 价值观标签（可增删的字符串列表）；
- 发展历程（`year / title / desc` 结构化行，可增删）；
- 能力资质（`title / desc` 结构化行，可增删）。

> 保存后页面会**重新拉取**服务端数据回填，确认 JSON 字段（价值观 / 时间轴 / 能力）往返一致。

### 4.6 网站配置（`/site`，单例）

整页分区编辑后**一次性保存**，覆盖**公司信息 + 联系方式 + 页脚 + SEO**：

| 分区 | 字段 |
| --- | --- |
| 公司信息 | 公司名称（**唯一必填**）、标语、公司简介、Logo（**上传**） |
| 联系方式 | 联系电话、联系邮箱、联系地址、工作时间、地图占位图（**上传**） |
| 页脚 | 版权文案、备案号、社交链接（`label / url / icon` 结构化行，可增删） |
| SEO | 标题、描述、关键词 |

**生效范围（改完刷新前台即见）**：

| 前台位置 | 用到的配置 |
| --- | --- |
| Navbar | 公司名称（Logo 的 `alt`）、Logo 图片 |
| Footer | 公司名称、简介、标语、电话 / 邮箱 / 地址 / 工作时间、版权、备案号、社交链接 |
| 联系页 | 电话 / 邮箱 / 地址 / 工作时间、地图图、SEO 描述 |
| 全站 SEO | `<title>` 与 `meta[description/keywords]`、`og:*` |

> **重要：以下三项刻意不在后台可改范围**，以静态配置为准：
>
> | 项 | 原因 |
> | --- | --- |
> | **导航菜单**（`nav`） | 配错路径会直接导致前台 **404**，风险高于收益 |
> | **页脚快速链接**（`footer.quickLinks`） | 与导航菜单**同源**，避免两处不一致 |
> | **主题色**（`theme`） | 受**构建期 Tailwind 编译**约束，运行时改色需整体改为 CSS 变量注入（独立课题） |

**空值兜底**：某一项留空（或 `site_config` 尚未配置）时，前台**自动回退**到
`frontend/src/config/site.config.ts` 的静态值，不会出现空白。因此首次上线即使不配置
本页，网站也保持完整可用。

> 保存后页面会**重新拉取**服务端数据回填，确认往返一致。

### 4.7 留言管理（`/messages`）

- 字段展示：姓名 / 公司 / 电话 / 邮箱 / 内容摘要 / 提交时间 / 处理状态。
- 支持**关键词搜索**、**状态筛选**（全部 / 待处理 0 / 已处理 1）、分页。
- 行内「详情」查看完整留言（含来源 IP 与提交时间）；可**标记为待处理 / 已处理**（写入处理时间）；
  可**删除**（二次确认）。
- 安全：留言管理接口位于后台前缀下并**强制鉴权**，匿名调用返回 `1003`。

### 4.8 账号管理（`/accounts`）

为**多名**运营人员各开一个后台账号（「一人一账号」，便于追溯与各自改密）。
**注意：账号之间权限完全相同**——本模块**不做角色 / 权限区分**（RBAC 为后续独立课题）。

| 操作 | 说明 |
| --- | --- |
| **新建账号** | 输入账号名（**字母开头**，3–50 位，可含字母 / 数字 / `_` / `-`）→ 系统**自动生成一次性随机强密码**并弹窗展示 |
| **凭据面板** | 新建 / 重置成功后弹出示账号名 + 密码，含**复制**按钮，并明确提示「**仅本次展示**」——关闭后无法再查看，请当场复制并安全传递给本人 |
| **停用 / 启用** | 行内按钮切换。**停用（推荐）**为可逆软删；停用后该账号**立即被踢下线**，所有 Token 失效 |
| **重置密码** | 二次确认后重新生成一次性随机密码；该账号被标记「待改密」并**立即踢下线**；拿到新密码的本人下次登录会被强制改密 |
| **删除（硬删）** | 二次确认弹窗中**需手动输入该账号名**才能执行，删除后**不可恢复**（如需保留请改用「停用」） |
| **主账号标记** | 账号名旁若显示「**主账号**」，说明它是系统初始化时创建的**初始管理员**（`is_primary = 1`）。该行「停用」「删除」按钮**永久置灰** |

**安全约束（系统强制，按钮会置灰）**：

1. **不能停用 / 重置 / 删除「当前登录账号」**——防止把自己锁在后台之外（自己改密请去「修改密码」页）。
2. **不能重置自己的密码**——重置会生成一次性随机密码并强制改密，若作用于自己会导致当前密码失效、无法登录。
3. **主账号不可停用 / 不可删除**——初始管理员是系统的「归属锚点」，任何管理员都不能停用或删除它（无论操作者是谁）。
   但它**不代表权限更高**：管理员之间权限仍然完全一样，该标记只是一道防误删护栏。
   注意：主账号**可以**被「启用」（若因历史原因处于停用态）与「重置密码」（保留密码找回路径）。
4. **至少保留 1 个启用账号**——停用 / 删除**启用中**账号时，若会导致全站无启用账号，系统直接拒绝。
5. **账号名不可重复**（包含已停用的账号）——重复创建返回 `1002`。
6. **不显示密码哈希**——密码只在新建成 / 重置时以明文**一次性**返回，数据库中仅存 bcrypt 哈希。

> **主账号是怎么来的？** `php think cms:init` 首次创建管理员时，会把该账号直接标为主账号。
> 老库升级时，若库中还没有主账号，建表脚本会把**最早创建**的那个管理员（`id` 最小）回填为主账号，
> 保证任一时刻**恰好有 1 个**主账号。后台**没有**「转移主账号」的按钮——如需更换，请走命令行 / 数据库操作。

> **新账号首次登录**：需用一次性密码登录 → 被强制跳「修改密码」页 → 改密完成后才能进入其它模块。

### 4.9 操作日志（`/oplogs`）

「操作日志」是后台的**审计流水**，用来回溯「**谁、在什么时候、对哪个对象、做了什么、成功与否**」。
导航项位于「**账号管理**」与「**修改密码**」之间；进入后**默认查询最近 7 天**的记录。

**怎么看**

- **列表列**：时间 / 操作人 / 模块 / 动作 / 目标对象 / 结果 / IP / 操作（「详情」）。
- **筛选**（可组合）：模块、操作人（`admin_name`）、结果（成功 / 失败）、关键词、开始日期、结束日期。
  「关键词」对**目标名称与详情文本**做模糊匹配；未指定日期时按**最近 7 天**兜底（避免全表扫描）。
- **分页**：每页 10 / 20 / 50 可选；列表按**时间倒序**（最新在前）。
- **详情抽屉**：只读展示全部字段（含目标、完整详情、来源 IP 与浏览器 UA），并固定提示
  「**操作日志为审计流水，不可修改、不可删除**」。
- 「重置」一键清空全部筛选条件并回到默认 7 天窗口；「查询」按钮与回车均可提交。

**会记什么（模块 / 动作覆盖）**

登录 / 登出 / 修改密码 / 重置密码；产品、新闻、案例、优势、关于我们、网站配置的
**新增 / 编辑 / 删除**；留言的**标记状态 / 删除**；图片**上传**；账号的
**新建 / 启用 / 停用 / 重置密码 / 删除**。每类操作均记录**成功与失败**两种结果——
**校验失败也会留痕**（`result=0`，详情写明失败原因）。

**不记什么（刻意不采集，属安全设计）**

1. **任何读写/查询类操作**（列表、详情、前台读取）——只记**会改变状态**的动作，控制日志量。
2. **密码明文与哈希**——改密 / 重置密码的日志只写「成功 / 失败」与原因，**绝不写密码内容**
   （重置后一次性随机密码同样不入日志）。
3. **Token / 会话串**——登录成功只记账号与来源，不记签发的 Token。
4. **请求体原文**——不整包落库，只记**提炼后的摘要**（如「变更字段：name, summary」）。
5. **登录失败原因统一**——账号不存在与密码错误**统一**记为「账号或密码错误」，防账号枚举。

> **日志不可篡改**：操作日志为**只追加**（append-only）流水，后台**没有**编辑 / 删除入口；
> 数据表中亦无对应写接口，仅由系统在业务动作发生时自动写入。
> **保留策略**：日志默认保留 `OPLOG_RETAIN_DAYS` 天（示例 `180` 天），
> 由运维定时执行 `php think oplog:clean` 清理过期数据（该命令自身**不写日志**）。

## 五、内容读取与「刷新即生效」机制

- 前台首页使用**聚合接口** `/api/home/summary` 一次取回产品 / 优势 / 案例 / 新闻摘要（最少请求数）。
- **站点配置**走独立接口 `GET /api/site/config`：返回的仅是**业务字段**
  （`companyName / logo / slogan / description / contact / footer / seo`），
  不含 `nav` / `theme` / `footer.quickLinks`——这三项由前端静态配置补齐后合并。
- 列表页 / 详情页 / 关于我们分别调用对应的公共内容接口（匿名只读）。
- **缓存**：前端内存缓存 + 后端短 TTL（60s）缓存头；后台**保存 / 删除成功后前端清除内容缓存**，
  故**后台改完刷新前台即命中新数据**（网站配置保存同样会清缓存）。
- 若前台首次请求命中的是 60s 内的缓存，最迟 60s 后自动过期，或刷新页面即时生效。
- **降级兜底**：接口失败时，区块自动回退到 `frontend/src/data/*.ts` 的本地数据并展示轻提示，
  **不白屏**；恢复后端后点击「重新加载」即可回到线上数据。
  站点配置的兜底更彻底：`SiteConfigProvider` 以静态配置作为**同步初始值**，
  接口成功才覆盖，因此**首帧即有内容、无闪烁**，接口故障时前台与改造前完全一致。

## 六、生产部署（Nginx 同域示例）

同名同域部署：前端静态产物 + 后端 TP8，同一域名下 `/api` 与 `{CMS_PATH}/api` 反代到后端。

```nginx
server {
    listen 80;
    server_name www.example.com;

    root /var/www/corporate-site/frontend/dist;
    index index.html;

    # ===== 后台上传的图片 =====
    # `^~` 至关重要：否则会被下方通用静态资源正则 location 抢先匹配，
    # 导致到 frontend/dist/uploads/ 下找不到文件而 404。
    # 目录内 `.htaccess` 仅对 Apache 生效；Nginx 用下面的 if 完成等价加固。
    location ^~ /uploads/ {
        alias /var/www/corporate-site/backend/public/uploads/;

        # 仅允许图片扩展名访问（含 .php 等一律 403）
        if ($uri !~* \.(?:jpg|jpeg|png|gif|webp)$) {
            return 403;
        }

        add_header X-Content-Type-Options "nosniff" always;
        expires 30d;
        add_header Cache-Control "public";
    }

    # ===== 后台管理 API（须置于通用 SPA 回退之前）=====
    # {CMS_PATH} 与实际配置一致，例如 /manage-x7k2
    location /manage-x7k2/api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # ===== 前台公共 API =====
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # ===== 前台 SPA 路由回退（含 /products /news /about 等）=====
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico|woff2?)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

> 说明：
> - **只**把 `/api` 与 `{CMS_PATH}/api` 反代到后端；`{CMS_PATH}` 下的**页面路由**
>   （如 `/manage-x7k2/login`）交给前端 SPA（回落 `index.html`），无需为后台单独配置 SPA 回退——
>   通用 `location /` 的回退已覆盖。
> - 若开启了独立的后台子路径 SPA 回退（把 `{CMS_PATH}` 也 `try_files ... /index.html`），
>   请确保**该规则位于 `{CMS_PATH}/api` 反代规则之后**，避免吞掉管理 API 请求。
> - Windows + ServBay 环境同理：`root` 指向 `dist`，反代指向 `php think run` 或 php-cgi 的 8000 端口。

## 七、常见问题（FAQ）

1. **访问后台地址显示 404？**
   确认前后端 `VITE_CMS_PATH` / `CMS_PATH` 已配置且**完全一致**（含前导 `/`，不含尾斜杠），
   配置后需**重启**前端构建与后端服务使其生效。

2. **登录提示「请先修改初始密码」？**
   首次登录使用初始化密码时会强制跳转改密页，改密后即可进入。

3. **登录提示锁定？**
   连续失败 5 次会锁定 10 分钟（账号 + IP 双维度）。等待锁定结束后重试，或用正确密码从另一网络登录。

4. **后台改了内容，前台没变？**
   前台内容 GET 有 60s 内存缓存；后台保存成功后已清缓存，**刷新前台页面**即可看到新内容。
   若仍无变化，确认前台访问的是同一后端服务（域名 / 端口一致）。

5. **前台某区块显示的是旧数据 / 顶部有加载失败提示？**
   说明该次接口请求失败，已**降级展示本地 `data/*.ts` 兜底数据**。检查后端是否运行、
   数据库连接是否正确；恢复后点击区块「重新加载」。

6. **新增产品 / 新闻报「该 id 已存在」？**
   `id` 为业务主键（slug），需要全局唯一。换一个 id 再提交即可：
   自动生成模式下点「**换一个**」重新生成，或点「手动指定」自定义。

7. **优势管理为什么没有 id 输入框？**
   优势表使用**自增数字主键**，新增时无需填写 id；编辑时系统携带记录 id。

8. **改了 `CMS_PATH` 后原后台地址失效？**
   属预期行为：路径即配置值，前后端需同步修改并重启；未配置（空）则该前缀整体 404。

9. **图片上传失败 / 提示「仅支持 jpg / png / webp / gif」？**
   后端以文件**真实内容**（而非扩展名）判定格式。若把其他格式的文件改名成 `.png` 上传，
   会因 MIME 与扩展名不匹配被拒绝 —— 这是**预期**的安全防护，请改用真实图片格式。

10. **上传成功但图片显示不出来（404）？**
    开发期确认 Vite 已代理 `/uploads`（见第一节）；生产环境确认 Nginx 已配置
    `location ^~ /uploads/`（见第六节，注意 `^~` 不可省略，否则会被静态资源正则抢走）。

11. **上传的图片存在哪里？会进 Git 吗？**
    存于 `backend/public/uploads/{product|news|case}/`，文件名为随机串。
    该目录下**除 `.htaccess` / `.gitkeep` 外的运行时文件已在 `.gitignore` 中忽略**，
    不会提交进仓库；迁移 / 备份服务器时需**单独同步该目录**。

12. **删除了内容记录，对应的图片会被删除吗？**
    不会。为避免误删仍被其他记录引用的图片，删除记录**不联动删除文件**。
    如需清理，请定期人工核对 `backend/public/uploads/` 下的孤儿文件。

13. **「网站配置」里为什么没有导航菜单和主题色？**
    刻意不提供：导航菜单配错路径会直接导致前台 **404**，且与页脚快速链接同源；
    主题色受**构建期 Tailwind 编译**约束，运行时改色需整体改为 CSS 变量注入。
    这三项以 `frontend/src/config/site.config.ts` 为准。

14. **网站配置里某项留空了，前台会显示空白吗？**
    不会。留空（或 `site_config` 未配置）时前台**自动回退**到静态配置的对应值，
    首次上线即使不配置本页网站也保持完整可用。

15. **改了网站配置，为什么前台某处没变？**
    先确认该处**是否在生效范围内**（见 4.6 表格）——导航菜单、页脚快速链接、主题色
    三项不受后台影响。若在范围内，刷新一次前台页面即可（保存时已清前端缓存）。

16. **「修改密码」页为什么和登录页长得不一样？**
    两者定位不同：**登录页 / 首次强制改密页**是登录前的闸门页，**独立整屏**、无后台外壳；
    **常规修改密码页**是登录后才能进的日常功能页，**在后台外壳之内**（左侧有导航、顶部有条），
    可从侧栏「修改密码」或顶栏按钮进入，改完能直接切回其它模块。

17. **点顶栏「修改密码」后，左侧导航没了？**
    正常版本不会。该页与产品/新闻等管理页一样套在后台外壳内，左侧导航与顶部条**始终保留**。
    若遇到只是孤零零一张卡片、没有侧栏，说明前端资源未更新 —— 请**硬刷新**（`Cmd/Ctrl + Shift + R`）。

18. **新建账号后，密码只显示一次，忘了怎么办？**
    出于安全考虑，密码只在新建 / 重置成功时以明文**一次性**返回，关闭凭据面板后无法再次查看。
    忘记时由任一管理员在其行上点「**重置密码**」，会生成新的**一次性**密码（并在凭据面板展示），
    本人用新密码登录后会被**强制改密**。

19. **为什么「停用 / 重置密码 / 删除」按钮是灰的？**
    那一行是**当前登录账号**：系统禁止对自身执行这三项操作——停用 / 删除会把自己锁在后台外；
    重置会生成一次性密码并强制改密，导致自己当前密码失效。**改自己的密码请到「修改密码」页**。

20. **停用或删除账号时报「至少保留一个启用账号」？**
    这是**保底约束**：停用 / 删除**启用中**账号时，系统必须保证全站至少还有 1 个启用账号，
    否则会拒绝。请**先启用 / 新建另一个账号**，再操作当前账号。

21. **「停用」和「删除」怎么选？**
    优先用「**停用**」——它是可逆的软删，停用后该账号立即被踢下线、无法登录，但记录仍在，
    随时可再「启用」。只有确定**不再需要**该账号时才用「删除」，且需在弹窗中**手动输入账号名**
    二次确认，删除后**不可恢复**。

22. **账号之间可以设置不同权限吗（比如只读账号）？**
    暂不支持。当前**所有管理员权限完全相同**（「一人一账号」用于追溯与各自改密），
    角色 / 权限体系（RBAC）为后续独立课题。

23. **某个账号旁的「停用」「删除」按钮是灰的，点不动？**
    看这行的标记：
    - 若显示「**当前登录**」——这是你自己。三个按钮都不可用（不能停用 / 重置 / 删除自己），改自己的密码请去「修改密码」页。
    - 若显示「**主账号**」——它是系统初始化时创建的**初始管理员**，「停用」「删除」永久禁用，
      防止误删后无法追溯系统归属。换一个非主账号操作即可；「重置密码」仍可用。

24. **「操作日志」里为什么看不到我刚才查列表 / 看详情的动作？**
   属**预期**：日志只记**会改变数据状态**的动作（登录 / 增删改 / 上传 / 账号操作等），
    纯读取（列表、详情、前台浏览）**不记**，以免日志量膨胀。

25. **为什么日志里有些记录是「失败」？失败动作也记吗？**
    记。审计流水需要还原**尝试过什么**：校验失败、登录失败、被守卫拒绝（如主账号不可停用）
    等同样会落一条 `result=0` 的记录，并在「详情」里写明失败原因（原因均为**脱敏**后的中文，不含密码 / Token）。

26. **能删除或修改某条操作日志吗？**
    不能，且这是**刻意设计**。操作日志为**只追加**的审计流水，后台无编辑 / 删除入口，
    数据表也无对应写接口。日志默认保留 `OPLOG_RETAIN_DAYS` 天（示例 `180` 天），
    由运维定时执行 `php think oplog:clean` 清理**过期**数据。

27. **「操作日志」页打开是空的？**
    默认只查**最近 7 天**。若近期无写操作，即为空属正常。可放宽「开始 / 结束日期」范围再查询；
    点「重置」可一键回到默认 7 天窗口。

24. **主账号是不是权限更大的「超级管理员」？**
    **不是。** 主账号只多了一道「不可被停用 / 删除」的保护，**权限和其他管理员完全相同**，
    也不能查看或修改别人的密码。它存在的意义只是「别把初始入口弄丢」。

25. **主账号的密码忘了怎么办？**
    用另一个管理员账号登录 →「账号管理」→ 找到主账号那一行 →「**重置密码**」→
    会生成一次性新密码（仅展示一次），交给主账号的使用者，其下次登录会被强制改密。
    这也是为什么主账号**允许**被重置密码——否则忘记密码就只能走命令行。

26. **能把主账号转让给别人 / 换一个账号吗？**
    后台**没有**这个按钮（避免主账号被随意换手或出现多个）。如确有需要（例如原主账号的使用者离职），
    请让技术人员在命令行 / 数据库侧操作 `admin_user.is_primary`——操作完请保持**全库只有 1 个**主账号。
