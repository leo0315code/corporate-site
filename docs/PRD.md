### 原始需求复述

## 二、技术栈与前后端约定

### 2.1 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | Vite + React + React Router + Tailwind CSS | 单页应用（SPA），响应式，PC/移动端自适应 |
| 后端 | ThinkPHP 8（Composer 安装：`composer create-project topthink/think`） | 成熟国产 PHP 框架，内置路由、验证器、中间件、ORM，开发效率高 |
| 数据存储 | MySQL 8（主方案） | 兼容 ServBay 自带 MySQL 8.0，连接账号 root/root |
| 备选存储 | SQLite | 轻量备选，无 MySQL 环境时可切换（仅需改数据库配置） |
| 后端分层 | Controller + Service + Model（TP8 `app/` 目录结构） | 参数校验使用 TP8 的 Validate 验证器 |
| 部署 | 前端静态产物 + TP8 后端同域部署 | Nginx 反向代理 `/api`，兼容 ServBay 与 Windows 服务器 |

> **为什么用 MySQL 8 而非 SQLite**：用户本地 ServBay 已自带 MySQL 8.0，无需额外安装；MySQL 更适合后续扩展（后台多用户、并发写入、数据统计、数据可视化）。SQLite 仅作为无 MySQL 环境时的轻量备选，写在文档供备选参考，主方案统一使用 MySQL 8。

### 2.2 前后端接口对应关系（不涉及具体代码）

| 接口 | 方法 | 用途 | 优先级 | 前端调用页面 |
| --- | --- | --- | --- | --- |
| `/api/message` | POST | 提交留言（含字段校验、防重复提交） | P0 | 联系我们页 / 全站留言弹窗 |
| `/api/message/list` | GET | 查看留言列表 | P2 | 后台管理页（可选） |

- **统一响应格式**：`{ "code": 0, "message": "ok", "data": {...} }`，`code = 0` 表示成功，`code != 0` 表示业务失败。
- 前端通过 `fetch` 调用 TP8 接口；**开发期前端运行在 `5173`、后端运行在 `8000`**，由后端 CORS 跨域中间件放行（开发期），或使用 Vite proxy 将 `/api` 转发到 `8000`。
- 参数校验交由 TP8 的 **Validate 验证器**（服务端二次校验，不可信任前端）。
- 生产部署：前端 `npm run build` 静态产物 + TP8 后端同域部署，Nginx 反向代理 `/api` 到 TP8 入口。

### 2.3 数据表结构

**`message` 表（留言表）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | int（主键，自增） | 留言 ID |
| name | varchar(30) | 姓名 |
| company | varchar(50) | 公司名称（选填，可空） |
| phone | varchar(20) | 电话 |
| email | varchar(100) | 邮箱 |
| content | varchar(500) | 留言内容 |
| ip | varchar(45) | 提交者 IP（用于防刷与审计） |
| created_at | datetime | 创建时间 |

### 2.4 页面与接口对应

| 页面 | 路由 | 数据来源 | 是否调用后端接口 |
| --- | --- | --- | --- |
| 首页 | `/` | 站点配置 + 内容数据文件 | 否 |
| 关于我们 | `/about` | 站点配置 + 内容数据文件 | 否 |

## 三、产品定位

### 3.1 产品目标

1. **建立企业线上门面**：为中小企业提供一套开箱即用的官网，让访客在 30 秒内理解「这家公司是谁、做什么、怎么联系」，替代「无官网」或「过时官网」的现状。
2. **高效获客与转化**：通过清晰的产品服务展示与低门槛的联系/留言入口，将访问流量转化为销售线索（Lead）。
3. **一次开发、多企业复用**：通过内容配置化（站点配置文件 + 数据文件）实现换公司名、Logo、电话、产品、新闻即可上线，无需改动页面代码，满足大部分行业通用需求。

### 3.2 目标用户

| 角色 | 描述 | 核心诉求 |
| --- | --- | --- |
| 访客 / 潜在客户 | 通过搜索、名片、广告等渠道进入官网的客户 | 快速了解公司实力与产品，方便地发起联系 |
| 企业运营 / 内容维护者 | 负责维护官网内容的非技术人员 | 低成本更新公司信息、产品、新闻，无需改代码 |
| 部署方 / 开发者 | 部署与二次开发官网的技术人员 | 结构清晰、配置集中、易部署、易扩展 |

### 3.3 成功度量（用于验收参考）

- 首屏 1 屏内可见公司定位与核心入口；核心页面 LCP < 2.5s。
- 移动端（375px 宽）无横向滚动、无内容溢出、关键按钮可点击。
- 留言提交成功率 100%（正常网络），表单校验错误提示明确。
- 更换站点配置（公司名/Logo/联系方式）后全站文案同步生效，无需改组件代码。

## 四、用户故事

1. **作为访客**，我希望在首页一屏内看到公司是做什么的、有什么优势，以便快速判断这家公司是否与我的需求相关。
2. **作为潜在客户**，我希望浏览「产品服务」页面并按分类查看每项服务详情，以便了解我能得到的价值与解决方案。
3. **作为潜在客户**，我希望在「新闻中心」看到公司动态与行业资讯，以便评估公司的专业度与活跃度。
4. **作为潜在客户**，我希望通过「联系我们」页面查看电话、邮箱、地址、地图，并能直接提交留言，以便随时发起咨询。
5. **作为移动端访客**，我希望在手机上也能顺畅浏览、点击导航和提交留言，体验与 PC 一致，以便在碎片时间完成了解与联系。
6. **作为企业运营人员**，我希望只修改一个配置文件就能替换公司名称、Logo、联系方式、产品与新闻，以便快速交付不同企业的官网。

## 七、留言功能需求

### 7.1 表单字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 姓名 name | 文本 | 是 | 2~30 字符 |
| 公司 company | 文本 | 否（选填） | 0~50 字符 |
| 电话 phone | 文本 | 是（与邮箱二选一必填其一） | 支持手机号/座机，基础格式校验 |
| 邮箱 email | 文本 | 否（与电话至少填一项） | 邮箱格式校验 |
| 留言内容 content | 多行文本 | 是 | 5~500 字符 |
| 提交 IP ip | 后端生成 | — | 提交者 IP，用于防刷审计 |
| 提交时间 created_at | 后端生成 | — | 服务器时间戳 |

### 7.2 校验规则

- **前端校验**：必填项非空、长度范围、邮箱正则、电话格式、内容长度；错误时字段下方红字提示，不提交。
- **后端校验**：使用 TP8 **Validate 验证器**做服务端二次校验（不可信任前端），校验不过返回 `code != 0` 及错误信息。
- 姓名长度 2~30；留言内容 5~500；电话/邮箱至少填一项。

### 7.3 提交与反馈

- 提交时按钮**置灰 + Loading 文案**（如「提交中…」），防止重复点击。
- 成功：显示 Toast/内联提示「提交成功，我们会尽快与您联系」，并清空表单。
- 失败：显示明确错误原因（网络异常 / 校验失败），表单内容保留，便于重试。

### 7.4 防重复提交

- 前端：提交中禁用按钮；提交成功后设置短时冷却（如 30s）。
- 后端：同 IP + 同内容在 60s 内重复提交判定为重复，直接返回成功但不重复入库（幂等）。
- （P2）可加图形验证码增强防刷。

### 7.5 隐私与合规

- 表单下方提示「提交即表示同意我们联系您」，不收集无关个人信息。
- 留言数据仅用于业务联系。

## 九、通用性要求（如何满足大部分企业）

核心思路：**页面结构通用化 + 内容配置化**，换企业只改数据，不改代码。

1. **站点配置文件 `site.config`**（统一入口，建议 `src/config/site.ts` 或 `public/site.json`）：
   - 公司名称、Logo、标语/价值主张
   - 导航菜单项
   - 联系方式：电话、邮箱、地址、工作时间、地图信息
   - 页脚内容、备案号、社交链接
   - 主题色（可选，覆盖 `--color-primary`）
2. **内容数据文件**（建议 `src/data/` 下 JSON/TS）：
   - `products`：产品/服务列表（含 id、分类、名称、简介、详情、图片）
   - `news`：新闻列表（含 id、标题、日期、封面、摘要、正文）
   - `about`：公司简介、发展历程、团队/资质
   - `cases` / `advantages`：案例与优势（可选）
3. **组件无行业绑定**：所有区块文案、图标、图片均来自配置/数据，组件内不写死公司名或行业词。
4. **图片可替换**：使用占位图 + 统一图片目录，部署方按命名替换即可。
5. **扩展方式**：新增页面/产品/新闻只需在数据文件加条目，路由自动渲染。

> 交付时应附「使用说明」：改哪几个文件即可换成另一家公司的官网。
